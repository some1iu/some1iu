## Claims in the CV and their evidence

- **Schema shape** (`user`/`movie`/`bill` columns): from the `INSERT INTO user`, `INSERT INTO bill` and
  `SELECT` statements in the source.
- **Filter-driven query builder**: `search_movies()` starts from `SELECT * FROM movie WHERE 1=1` and
  appends `AND` clauses per supplied criterion (`LIKE %…%` for title).
- **Parameterised queries**: `%s` placeholders with a params list in `search_movies()` and the
  `Binary_Data`/`INSERT INTO user` statements.
- **Recommendations**: `SELECT * FROM movie WHERE Genre IN` built from the user's `PG1`–`PG3` columns on
  the home screen — *not* a ranking or collaborative-filtering system.
- **BLOB handling**: `SELECT Binary_Data ... ` then written to `Stream.png`.
- **Error handling**: single `handle_errors()` catching `Error`, `EOFError`, `ValueError`, `KeyError`,
  `TypeError`.
- **No tests**: the repo has no test files; the CV says correctness was checked by hand.
- **ACM Incursion**: repo-level facts (envelope, 400/401/403/409, sessionStorage token, JWT, role tiers,
  Zod, `Decimal(12,2)`, 39 Jest tests, E2E script) are verified in the code — I ran `grep` against them.
  Which of these *you* personally wrote is not verifiable (every commit is authored by `chetisha28`), so
  the CV hedges with "contributed to … parts of" and names the project as a team build.
