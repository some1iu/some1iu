\project{Movie Streaming Platform}{Python, MySQL}
\meta{Independent project \;\textbullet\; single module, $\approx$820 lines \;\textbullet\;
      \href{https://github.com/some1iu/movie-streaming-platform}%
           {github.com/some1iu/movie-streaming-platform}}
\begin{itemize}
  \item Built a console application that lets a user register and log in, browse a movie catalogue by
        title, genre and release year, and rent or buy a title, with an itemised bill written to disk
        at the end of each transaction.
  \item Modelled the data in three tables and implemented every access path against them: \texttt{user} (username, name, password, three preferred genres, access level),
        \texttt{movie} (code, title, year, rating, genre, summary, rent and buy cost, binary asset) and
        \texttt{bill} (transaction number, date, rent/buy flag, movie code, user).
  \item Wrote a filter-driven query builder that appends \texttt{WHERE} clauses only for the criteria
        the user actually supplies --- \texttt{LIKE} matching for titles, exact matching for genre and
        year --- and used parameterised statements on the registration and search paths so user input
        is bound rather than concatenated.
  \item Generated recommendations by reading the user's three stored genre columns and building them
        into an \texttt{IN} query on the home screen; handled the receipt side with file handling, and
        stored movie image data as a \texttt{BLOB} that is written back out to a file when a
        transaction completes.
  \item Funnelled the risky call sites through one error handler covering
        \texttt{mysql.connector} errors, bad input, type and key errors, so an invalid entry returns
        the user to the menu instead of terminating the session. No automated tests yet; correctness
        was checked by exercising each flow by hand.
\end{itemize}
